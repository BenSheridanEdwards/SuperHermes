# Create Agent (SuperHermes)

**Build one excellent, self-contained Hermes agent — correct from day one.** This
skill is the operating manual for SuperHermes's `new-agent`. It produces a *complete*
agent; it does **not** wire it into any particular fleet (remotes, shared tier
matrix, shared secrets). That boundary is deliberate — fleet integration is a layer
above, and keeping it out is what lets this stay open-source and fleet-agnostic.

> **Scope contract.** Done = an agent that passes `verify-fleet --agent <Name>`
> (0 fail). Output = a self-contained agent at `AGENTS_ROOT/<Name>/` with a running
> gateway, Honcho stack, and GBrain. NOT yet a fleet member.

`REPO` below = the SuperHermes checkout (e.g. `/Users/agents/Agents/Shared/SuperHermes`).

## 1. Preflight (don't skip — the scaffolder assumes these)
- `superhermes.conf` exists (copy from `.example`) with `AGENTS_ROOT` + sandbox
  carve-outs set. Without it, `new-agent` uses example defaults.
- Docker is running (Honcho stack); **Bun** installed (GBrain); **Ollama** up on
  `:11434` (local embeddings). macOS (`sandbox-exec` + launchd).
- Name is PascalCase and the dir does not already exist. Ports auto-allocate to the
  next free triple (API/DB/Redis), so no manual port picking.

## 2. Dry-run first — always
```sh
"$REPO/bin/new-agent" --name <Name> --dry-run
```
Renders the entire anatomy to a temp dir with **zero side effects** and
**compile-checks the sandbox profile**. Confirm it completes cleanly before a real
build. (`bash "$REPO/tests/run-tests.sh"` also exercises the shipping scripts.)

## 3. Build
```sh
"$REPO/bin/new-agent" --name <Name> --camp <camp>   # interactive: name·camp
# --no-start  → scaffold files only (no Docker/launchd)
```
The 8 phases: skeleton → town-square **sandbox** (compile-checked) → Hermes
**profile** (config.yaml, honcho.json, SOUL seed, MEMORY/USER, `.env` secret keys,
**memory-maintenance + git-sync crons** + their scripts, normalised root
`.gitignore`) → **GBrain** (own v0.41 runtime + wrapper + pglite) → **Honcho stack**
(compose + `.env` + backup; on a fresh DB it builds the image and reshapes pgvector
to 768) → **launchd plists** → **permissions + `git init`** (the agent's own repo) →
**services** (Honcho up, GBrain installed + vault embedded, gateway started).

## 4. The human 5% (it pauses for these — they cannot be autogenerated)
- **`SOUL.md`** — the agent's persona. It is born with a *seed* ("a new soul with
  unlimited potential…"); you write who it becomes.
- **Secrets** — `<profile>/.env` keys (Telegram token from @BotFather, etc.), or a
  secrets manager. Backend-agnostic.
- **`auth.json`** — provider credentials.

## 5. Verify (the definition of done)
```sh
"$REPO/bin/verify-fleet" --agent <Name>     # MUST be 0 fail
```
Checks: sandbox compiles · own GBrain wrapper + profile-isolated store · no stale
shared-wrapper/LocalMem refs · cron scripts exist · normalised `.gitignore`, no
secrets tracked · honcho.json valid · `KeepAlive: true` · baseline crons present.

When this is green you have a **correct agent** — but an *island*. To make it a
fleet member (off-machine backup, shared model tiers, shared secrets), hand it to
the fleet's onboarding workflow. That is intentionally not this skill's job.
